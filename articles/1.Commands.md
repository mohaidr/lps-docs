
# Commands Documentation

This section provides a detailed reference for the commands and options supported by the **LPS Tool**.

---

## General Usage

The **LPS Tool** is used for Load, Performance, and Stress testing of web applications. Below is the general usage format:

```bash
lps [command] [options]
```

---

## Global Options

### Options:
- `-n`, `--name`, `--NAME <name>`: Specifies the plan name. Defaults to `Quick-Test-Plan`.
- `-rn`, `--roundname`, `--ROUNDNAME <roundname>`: Specifies the round name. Defaults to `Quick-Test-Round`.
- `-sd`, `--startupDelay`, `--startupdelay`, `--STARTUPDELAY <startupDelay>`: Adds a startup delay (in milliseconds) to your round.
- `-nc`, `--numberofclients`, `--NUMBEROFCLIENTS <numberofclients>`: Specifies the number of clients for the test round. Defaults to `1`.
- `-ad`, `--arrivaldelay`, `--ARRIVALDELAY <arrivaldelay>`: Specifies the time in milliseconds to wait before a new client arrives.
- `-dcc`, `--delayclientcreation`, `--DELAYCLIENTCREATION <delayclientcreation>`: Delays client creation until needed.
- `-rip`, `--runinparallel`, `--RUNINPARALLEL <runinparallel>`: Executes your iterations in parallel.
- `-s`, `--save`, `--SAVE`: Saves the test as a YAML or JSON file to disk. Defaults to `False`.
- `-u`, `--url`, `--URL <url>`: Specifies the URL for the test.
- `-hm`, `--httpmethod`, `--HTTPMETHOD`, `--method`, `--METHOD <method>`: Specifies the HTTP method. Defaults to `GET`.
- `-h`, `--header`, `--HEADER <header>`: Specifies custom headers for the request.
- `-in`, `--iterationname`, `--ITERATIONNAME <iterationname>`: Specifies the iteration name. Defaults to `Quick-Http-Iteration`.
- `-im`, `--iterationmode`, `--ITERATIONMODE <iterationmode>`: Defines the iteration mode. Defaults to `R`.
- `-mt`, `--maximizethroughput`, `--MAXIMIZETHROUGHPUT <maximizethroughput>`: Maximizes test throughput.
- `-rc`, `--requestcount`, `--REQUESTCOUNT <requestcount>`: Specifies the number of requests.
- `-d`, `--duration`, `--DURATION <duration>`: Specifies the duration in seconds.
- `-cdt`, `--cooldowntime`, `--COOLDOWNTIME <cooldowntime>`: Specifies the cooldown time in milliseconds.
- `-bs`, `--batchsize`, `--BATCHSIZE <batchsize>`: Specifies the batch size for requests.
- `-hv`, `--httpversion`, `--HTTPVERSION <httpversion>`: Specifies the HTTP version. Defaults to `2.0`.
- `-dhtmler`, `--downloadhtmlembeddedresources`, `--DOWNLOADHTMLEMBEDDEDRESOURCES`: Downloads embedded resources in HTML responses.
- `-sr`, `--saveresponse`, `--SAVERESPONSE <saveresponse>`: Saves HTTP responses.
- `-sh2c`, `--supporth2c`, `--SUPPORTH2C <supporth2c>`: Enables support for HTTP/2 over clear text.
- `-p`, `--payload`, `--PAYLOAD <payload>`: Specifies the request payload.
- `--clientcertificatepath <path>`: Specifies the path to a client certificate for mutual TLS authentication. Supported formats: `.pfx`, `.p12`, `.pem`, `.cer`, `.crt`.
- `--clientcertificatepassword <password>`: Specifies the password for the client certificate file.
- `-fr`, `--failurerule`, `--FAILURERULE <failurerule>`: Specifies a failure rule using inline metric expression format. Can be used multiple times. Format: `"metric[;errorStatusCodes]"` (e.g., `"ErrorRate > 0.05;>= 500"` or `"SkipRatio > 0.10"`).
- `-tr`, `--terminationrule`, `--TERMINATIONRULE <terminationrule>`: Specifies a termination rule using inline metric expression format. Can be used multiple times. Format: `"metric;gracePeriod[;errorStatusCodes]"` (e.g., `"ErrorRate > 0.10;00:05:00;>= 500"`).
- `--version`: Shows the version information.
- `-?`, `-h`, `--help`: Displays help and usage information.

## Commands

### `create`
#### Description:
Creates a test plan.
#### Usage:
```bash
lps create <config> [options]
```
#### Options:
- `--name <name>`: Specifies the plan name.
- `-?`, `-h`, `--help`: Displays help and usage information.

### `round`
#### Description:
Creates a new test round.
#### Usage:
```bash
lps round <config> [options]
```
#### Options:
- `-n`, `--name`, `--NAME <name>`: Specifies the round name.
- `-burl`, `--baseUrl`, `--baseurl`, `--BASEURL <baseUrl>`: Specifies the base URL of the target endpoint.
- `-sd`, `--startupDelay`, `--startupdelay`, `--STARTUPDELAY <startupDelay>`: Adds a startup delay (in milliseconds) to your round.
- `-nc`, `--numberofclients`, `--NUMBEROFCLIENTS <numberofclients>`: Specifies the number of clients. Defaults to `1`.
- `-ad`, `--arrivaldelay`, `--ARRIVALDELAY <arrivaldelay>`: Specifies the time in milliseconds to wait before each new client arrives.
- `-dcc`, `--delayclientcreation`, `--DELAYCLIENTCREATION <delayclientcreation>`: Delays client creation until needed.
- `-rip`, `--runinparallel`, `--RUNINPARALLEL <runinparallel>`: Executes your iterations in parallel.
- `-t`, `--tag`, `--TAG <tag>`: Adds a tag to the round to execute later by tag(s).
- `-?`, `-h`, `--help`: Displays help and usage information.

### `iteration`
#### Description:
Adds an HTTP iteration to a test round.
#### Usage:
```bash
lps iteration <config> [command] [options]
```
#### Options:
- `-rn`, `--roundname`, `--roundName`, `--ROUNDNAME <roundname>`: Specifies the round name.
- `-n`, `--name`, `--NAME <name>`: Specifies the iteration name.
- `-im`, `--iterationMode`, `--iterationmode`, `--ITERATIONMODE <iterationMode>`: Defines the iteration mode.
- `-sd`, `--startupdelay`, `--STARTUPDELAY <startupdelay>`: Adds a startup delay (in milliseconds) to your iteration.
- `-mt`, `--maximizethroughput`, `--MAXIMIZETHROUGHPUT <maximizethroughput>`: Maximizing test throughput. Maximizing the throughput will result in higher CPU and Memory usage [default: False].
- `-rc`, `--requestcount`, `--REQUESTCOUNT <requestcount>`: Specifies the number of requests for the iteration.
- `-d`, `--duration`, `--DURATION <duration>`: Specifies the duration of the iteration.
- `-cdt`, `--cooldowntime`, `--COOLDOWNTIME <cooldowntime>`: Specifies the cooldown time in milliseconds.
- `-bs`, `--batchsize`, `--BATCHSIZE <batchsize>`: Specifies the batch size for the iteration.
- `-hm`, `--httpmethod`, `--HTTPMETHOD`, `--method`, `--METHOD <method>`: Specifies the HTTP method.
- `-hv`, `--httpversion`, `--HTTPVERSION <httpversion>`: Specifies the HTTP version. Defaults to `2.0`.
- `-u`, `--url`, `--URL <url>`: Specifies the URL for the iteration.
- `-dhtmler`, `--downloadhtmlembeddedresources`, `--DOWNLOADHTMLEMBEDDEDRESOURCES`: Downloads embedded resources in HTML responses.
- `-sr`, `--saveresponse`, `--SAVERESPONSE <saveresponse>`: Saves HTTP responses.
- `-h2c`, `--supporth2c`, `--SUPPORTH2C <supporth2c>`: Enables support for HTTP/2 over clear text.
- `-h`, `--header`, `--HEADER <header>`: Specifies headers for the iteration.
- `-p`, `--payload`, `--PAYLOAD <payload>`: Specifies the request payload.
- `-g`, `--global`, `--GLOBAL`: Saves as a global iteration. Defaults to `False`.
- `-fr`, `--failurerule`, `--FAILURERULE <failurerule>`: Specifies a failure rule using inline metric expression format. Can be used multiple times. Format: `"metric[;errorStatusCodes]"` (e.g., `"ErrorRate > 0.05;>= 500"` or `"SkipRatio > 0.10"`).
- `-tr`, `--terminationrule`, `--TERMINATIONRULE <terminationrule>`: Specifies a termination rule using inline metric expression format. Can be used multiple times. Format: `"metric;gracePeriod[;errorStatusCodes]"` (e.g., `"ErrorRate > 0.10;00:05:00;>= 500"`).
- `-?`, `-h`, `--help`: Displays help and usage information.

#### `ref` Subcommand
References an existing global HTTP iteration from a round.

```bash
lps iteration ref <config> --roundname <roundname> --name <iterationname>
```

- `<config>`: Test configuration file to update.
- `-rn`, `--roundname <roundname>`: Existing round that will reference the iteration. Required.
- `-n`, `--name <iterationname>`: Existing global iteration to reference. Required.
- `-?`, `-h`, `--help`: Displays help and usage information.

### `capture`
#### Description:
Enables the capture of HTTP response and optionally headers during the execution of the test.
#### Usage:
```bash
lps capture <config> [options]
```
#### Options:
- `-in`, `--iterationname`, `--ITERATIONNAME <iterationname>`: Specifies the iteration name.
- `-rn`, `--roundName`, `--roundname`, `--ROUNDNAME <roundName>`: Specifies the round name.
- `-to`, `--TO <to>`: Specifies the variable which will hold the response.
- `-h`, `--header`, `--HEADER <header>`: Specifies headers to be captured.
- `-as`, `--AS <as>`: Reads the variable as (Text, JSON, or XML).
- `-mg`, `--makeGlobal`, `--makeglobal`, `--MAKEGLOBAL <makeGlobal>`: Stores the response as a global variable so it can be used across multiple rounds.
- `-r`, `--regex`, `--REGEX <regex>`: Applies a regex to the captured value if referenced and resolved.
- `-?`, `-h`, `--help`: Displays help and usage information.

- `-?`, `-h`, `--help`: Displays help and usage information.

### `master`
#### Description:
Starts LPS as the dedicated master node for a distributed load test.

#### Usage:
```bash
lps master <plan>
```

#### Arguments:
- `<plan>`: Path to the test plan used by the worker nodes.

#### Options:
- `-?`, `-h`, `--help`: Displays help and usage information.

#### Notes:
- The current node must match the master node configured with the `cluster` command.
- The master prepares the plan, hosts the dashboard, and aggregates metrics from the worker nodes.
- The command waits for at least the configured `ExpectedNumberOfWorkers` to register, with a minimum of one worker.
- After that registration barrier is reached, the command remains active until all registered active workers finish, including workers beyond the configured count, or until the command is stopped with Ctrl+C or Escape.
- Run the test command separately on each worker. The master does not start workers automatically.

---

### `cluster`
#### Description:
Configure cluster (master/worker) settings for distributed load testing.

#### Usage:
```bash
lps cluster [options]
```

#### Options:
- `-mip`, `--masternodeip <masternodeip>`: Specifies the master node IP address or hostname.
- `-gp`, `--grpcport <grpcport>`: Specifies the gRPC port for cluster communication.
- `-ew`, `--expectednumberofworkers <expectednumberofworkers>`: Specifies the minimum number of workers that must register before a master-only node continues orchestration. At least one worker is always required. This option is ignored when the master also runs as a worker and does not limit how many registered workers must finish before the master exits.
- `-miw`, `--masternodeisworker`: Treats the master node as a worker node as well (master will also execute test iterations).
- `-?`, `-h`, `--help`: Displays help and usage information.

### `dashboard`
#### Description:
Updates the persistent LPS dashboard settings. Options that are not provided keep their current values.

#### Usage:
```bash
lps dashboard [options]
```

#### Options:
- `-bid`, `--builtindashboard <true|false>`: Enables or disables the built-in dashboard UI.
- `-p`, `--port <port>`: Sets the dashboard port. The value must be between `1` and `65535`.
- `-rr`, `--refreshrate <seconds>`: Sets the metrics push and dashboard refresh interval. The value must be greater than `0`.
- `-?`, `-h`, `--help`: Displays help and usage information.

#### Example:
```bash
lps dashboard --builtindashboard false --port 8009 --refreshrate 5
```

### `record`
#### Description:
Launches a Playwright Chromium browser, records HTTP traffic, and creates or updates an LPS YAML or JSON test plan.

#### Usage:
```bash
lps record [output] [options]
```

#### Arguments:
- `[output]`: Output plan file. Supported extensions are `.yaml`, `.yml`, and `.json`. Defaults to `RecordedPlan.yaml`.

#### Options:
- `-n`, `--name <name>`: Sets the generated plan name. By default, the name is derived from the output file.
- `-u`, `--url <url>`: Opens this URL when the browser starts.
- `--headless`: Runs the browser without a visible window.
- `--install`: Installs the Playwright Chromium browser and exits.
- `-pf`, `--prompt-files`: Prompts for local paths for captured file uploads.
- `-a`, `--append`: Adds captured requests to an existing plan instead of overwriting it.
- `-up`, `--update`: Updates requests matching the same method, URL, and body; unmatched requests are added.
- `-rn`, `--round <roundname>`: Selects the round for captured requests or names the new round.
- `-nc`, `--number-of-clients <number>`: Sets the number of virtual clients in the generated round. Defaults to `1`.
- `-ad`, `--arrival-delay <milliseconds>`: Sets the delay between client arrivals. Defaults to `0`.
- `-rip`, `--run-in-parallel`: Runs the generated round's clients in parallel.
- `-rc`, `--request-count <number>`: Sets requests per client for each generated iteration. Defaults to `1`.
- `-d`, `--duration <seconds>`: Generates duration-based iterations instead of request-count-based iterations.
- `-tt`, `--think-time`: Writes recorded idle gaps as iteration startup delays.
- `-mtt`, `--max-think-time <milliseconds>`: Caps recorded think-time values.
- `-oh`, `--only-host <hosts...>`: Keeps only requests whose host exactly matches one of the supplied hosts.
- `-ih`, `--ignore-host <hosts...>`: Ignores requests to the supplied hosts.
- `-ip`, `--ignore-path <paths...>`: Ignores requests whose URL path or query contains a supplied value.
- `-ict`, `--ignore-content-type <types...>`: Ignores responses whose content type contains a supplied value.
- `-iext`, `--ignore-extension <extensions...>`: Ignores URLs with the supplied file extensions.
- `-im`, `--ignore-method <methods...>`: Ignores the supplied HTTP methods.
- `-irt`, `--ignore-resource-type <types...>`: Ignores the supplied Playwright resource types.
- `-ihdr`, `--ignore-header <headers...>`: Removes request headers by exact name or by prefix ending in `*`.
- `-mh`, `--minimal-headers`: Removes common browser fingerprint headers.
- `-?`, `-h`, `--help`: Displays help and usage information.

#### Examples:
```bash
lps record --install
lps record app.yaml --url https://www.example.com --only-host example.com
```

See [Recording a Test Plan from Browser Traffic](18.Record.md) for recording workflow, filtering, append, and update behavior.

### `httpclient`
#### Description:
Updates the persistent HTTP client connection, timeout, header validation, and server timing settings. Options that are not provided keep their current values.

#### Usage:
```bash
lps httpclient [options]
```

#### Options:
- `-mcps`, `--maxconnectionsperserver <number>`: Sets the maximum connections per server.
- `-pclt`, `--poolconnectionlifetime <seconds>`: Sets the pooled connection lifetime.
- `-pcit`, `--poolconnectionidletimeout <seconds>`: Sets the pooled connection idle timeout.
- `-cto`, `--clienttimeout <seconds>`: Sets the HTTP client request timeout.
- `-hvm`, `--headervalidationmode <mode>`: Registered for `Strict`, `Lenient`, or `RawPassthrough`, but currently not applied by the command binder.
- `-aho`, `--allowhostoverride <true|false>`: Registered by the command, but currently not applied by the command binder.
- `-sth`, `--servertimeheader <header>`: Sets the response header used to capture server processing time.
- `-stf`, `--servertimeformat <format>`: Sets the server timing format to `Auto`, `Milliseconds`, `Seconds`, or `ServerTiming`.
- `-?`, `-h`, `--help`: Displays help and usage information.

> **Current limitation:** `--headervalidationmode` and `--allowhostoverride` appear in command help, but the current `HttpClientBinder` does not bind them. Configure those two values directly under `LPSAppSettings:HttpClient` until the binder is corrected.

#### Example:
```bash
lps httpclient --maxconnectionsperserver 100 --clienttimeout 30
```

See [HTTP Client Configuration](8.ClientConfiguration.md) for details.

### `watchdog`
#### Description:
Updates the persistent resource protection thresholds used by the LPS watchdog. Options that are not provided keep their current values.

#### Usage:
```bash
lps watchdog [options]
```

#### Options:
- `-mmm`, `--maxmemorymb <megabytes>`: Sets the memory threshold that suspends test activity.
- `-mcp`, `--maxcpupercentage <percentage>`: Sets the CPU threshold that suspends test activity.
- `-cdmm`, `--cooldownmemorymb <megabytes>`: Sets the memory threshold for resuming activity.
- `-cdcp`, `--cooldowncpupercentage <percentage>`: Sets the CPU threshold for resuming activity.
- `-mcccphn`, `--maxconcurrentconnectionscountperhostname <number>`: Sets the connection threshold per host name.
- `-cdcccphn`, `--cooldownconcurrentconnectionscountperhostname <number>`: Sets the connection threshold per host name for resuming activity.
- `-cdrtims`, `--cooldownretrytimeinms <milliseconds>`: Sets how often LPS checks whether activity can resume.
- `-maxcp`, `--maxcoolingperiod <seconds>`: Sets the maximum cooling period.
- `-rca`, `--resumecoolingafter <seconds>`: Sets when cooling can resume after the maximum period.
- `-sm`, `--suspensionmode <Any|All>`: Suspends when any threshold or all thresholds are exceeded.
- `-?`, `-h`, `--help`: Displays help and usage information.

#### Example:
```bash
lps watchdog --maxmemorymb 1000 --maxcpupercentage 70 --cooldownretrytimeinms 2000
```

See [WatchDog Mechanism](6.WatchDog.md) for details.

### `influxdb`
#### Description:
Updates the persistent InfluxDB integration settings. Options that are not provided keep their current values.

#### Usage:
```bash
lps influxdb [options]
```

#### Options:
- `-ie`, `--influxdbenabled <true|false>`: Enables or disables InfluxDB integration.
- `-iu`, `--influxdburl <url>`: Sets the InfluxDB server URL.
- `-it`, `--influxdbtoken <token>`: Sets the InfluxDB authentication token.
- `-io`, `--influxdborganization <organization>`: Sets the InfluxDB organization.
- `-ib`, `--influxdbbucket <bucket>`: Sets the InfluxDB bucket.
- `-?`, `-h`, `--help`: Displays help and usage information.

When InfluxDB is enabled, the URL must begin with `http://` or `https://`, and the URL, token, organization, and bucket are required.

#### Example:
```bash
lps influxdb --influxdbenabled true --influxdburl http://localhost:8086 --influxdbtoken <token> --influxdborganization LPS --influxdbbucket LPS_Metrics
```

See [InfluxDB Integration](12.InfluxDBIntegration.md) for details.
