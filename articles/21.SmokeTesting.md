# Smoke Testing

A **smoke test** (also called a *shakeout test*) runs your workload with minimal concurrency—typically **1 to 5 virtual clients** for a few seconds or a small fixed request count—to verify that your test plan, target endpoint, authentication, captures, and environment work cleanly before you scale up load.

Run a smoke test first whenever you write a new LPS script, change target environments, or ship an API change.

---

## What a Smoke Test Answers

- **Script validity:** Do all URLs, headers, payloads, variable placeholders, and `capture` / `skipIf` rules execute without syntax or runtime errors?
- **Functional health:** Does the API return expected `2xx` responses under light traffic?
- **Baseline latency:** What does clean, contention-free response time (`P50` / `P95`) look like with almost zero queuing?

> **Rule of thumb:** If a system fails or violates latency targets with 3 clients, running a 200-client load or stress test wastes time and hides the root cause.

---

## Quick CLI Smoke Check

For a fast single-endpoint sanity check from the terminal before creating a YAML file, send a small sequential request count (`-rc`):

```bash
lps --url https://api.example.com/health -rc 10
```

---

## Runnable YAML Smoke Test Plan

**Example assumptions:** 3 virtual clients start 500 ms apart, each client sends 10 sequential requests (`mode: R`, `requestCount: 10` = 30 total requests), and strict `failureRules` require **0% server/client errors** (`>= 400`) and `P95` under `500` ms.

```yaml
name: ApiSmokeTest
variables:
- name: targetUrl
  value: https://api.example.com/resource
rounds:
- name: SmokeRound
  numberOfClients: 3
  arrivalDelay: 500
  iterations:
  - name: VerifyEndpoint
    mode: R
    requestCount: 10
    httpRequest:
      url: $targetUrl
      httpMethod: GET
    failureRules:
    - metric: "ErrorRate > 0"
      errorStatusCodes: ">= 400"
    - metric: "TotalTime.P95 > 500"
```

Run the plan with:

```bash
lps run ApiSmokeTest.yaml
```

---

## How This Traffic Behaves

1. **Gentle start:** 3 clients spawn 500 ms apart over 1 second.
2. **Deterministic request total:** `mode: R` with `requestCount: 10` sends exactly 10 requests per client (30 requests total) and exits in seconds.
3. **Zero-tolerance grading:** Unlike high-load or stress tests that may tolerate small error percentages, smoke tests usually check `"ErrorRate > 0"` across `">= 400"` so broken auth (`401`/`403`), bad routes (`404`), and server errors (`5xx`) fail immediately.

---

## Best Practices

- **Keep concurrency tiny (`1–5` clients):** More than 5–10 clients turns a smoke check into a mini-load test.
- **Test multi-step journeys at 1 client first:** When building login → cart → checkout flows with `runInParallel: false` and `capture`, run with `numberOfClients: 1` first to confirm session correlation before testing concurrent clients.
- **Save the numbers as your clean baseline:** Record the smoke test's `P50` and `P95` latency so you can see how much queuing adds during [Load Testing](22.LoadTesting.md).
